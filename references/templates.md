# 模板骨架全文

主文件 `SKILL.md` 只放判据与流程，本文件放各类型骨架的完整章节清单，出稿时按判定的类型读对应小节。
判据本身在 `SKILL.md` 的「章节取舍」与「多类型模板分支」，本文件不重复。

**通用前提**：本文件所有章节清单都是**上限**，不是配额。某节没有实质内容就整节不出现，不留占位句。

## 会议·常规

顺序即优先级，结论、决策、行动在前，讨论细节在后：

```
会议基本信息（含「会议性质」字段）
会议结论
关键决策（条件节：无决策整节删除）
待办事项（条件节：无待办整节删除）
无人认领事项（条件节：无 Orphan 整节删除）
风险与顾虑（条件节）
时间线（条件节）
分歧与转折条件（条件节，研讨交流型优先）
待定与开放问题
上期行动项回顾（仅当提供了上期材料或有跨会索引命中）
会议内容
```

**必填只有「会议结论」与「会议内容」**，其余全部条件化。性质为研讨交流时，通常只有结论、待定与开放问题、分歧与转折条件、内容四节；性质为决策审批时，关键决策、风险与顾虑、时间线才是主角。

## 会议·正式（董事会／股东会／委员会）

常规骨架 + 法定要素节，插在会议基本信息之后（它回答「这次会议合不合法」，比结论更靠前）：

- **法定人数**：应到与实到人数，是否达到章程要求。材料没说写「材料未记录」，不按与会人数推断。
- **上次纪要批准**：通过 / 通过但有更正（写明更正处）/ 未表决。
- **动议与表决**：逐条列「动议原文 · 提议人 · 附议人 · 表决结果」。动议原文照录，不润色、不合并同类项。
- **回避与利益冲突**：谁就哪项议题声明回避。没有就删掉本条。
- **休会**：休会时间；有下次会议写日期。

三条硬约束：票数只按材料写出的数字记录，不推算；只提「通过了」没给票数时写「表决通过，票数材料未记录」；动议与其他议题混杂时单独摘出，不改写摘要。

**待办表加「对应动议」列**（八列），让「通过的动议有没有真被执行」可逐条核销。不涉及动议填「—」。

**审批脚注**（吸纳自 `pm-claude-skills` 的 `board-minutes`）：在文末加一行——
「本纪要提请下次会议批准」，或「本纪要已经 ×× 会议批准，批准日期 ××」。让这份记录知道自己处在哪个状态。

## 会议·复盘

四节，顺序固定：

1. **本次目标与结果**：当初定的目标、实际达到的结果，可对照并列。材料只有结果没目标时写「材料未记录原定目标」。
2. **做得好的**：要写具体到做法（「提前一天冻结需求」），不写「沟通顺畅」这类评价词。
3. **待改进**：出问题的环节及其原因。区分「流程问题」与「人的问题」，原因只能从材料里说的话来。
4. **下轮改进项**：表格（列同待办表），每条须能回指某条待改进，或明确标注为新增。

复盘不设「关键决策」节，因为通常不表决。完成标准是「读完知道下次哪一步会不一样」。

## 会议·站会

三节，总长控制在一屏内：

1. **进度**：按人或按事项，一行一条，写「做了什么」。
2. **计划**：接下来要做什么，一行一条。
3. **阻塞**：卡住的事项及卡在谁那里。没有阻塞写「本次未提出阻塞」，不省略本节。

不写讨论过程、不写背景、不加决策与待办表。若材料出现明确决策或跨人承诺，说明不是站会，改按常规会议出稿并说明判断依据。

## 会议亚型增量（吸纳自 pm-claude-skills）

常规会议之上按亚型追加几节，**不换整套模板**。判定凭「谁在场、产出什么」，与会议性质并行。

| 亚型 | 判据 | 追加节 |
| --- | --- | --- |
| 一对一（1:1） | 两人，含下属或上级，谈发展、反馈、困难 | 近期进展、挑战与困难、职业发展、双向反馈 |
| 冲刺计划 | 研发团队，定本轮做什么、估点、认领 | 冲刺目标、故事点与容量、依赖与阻塞、完成定义 |
| 产品评审 | 评审设计方案或功能，有过／不过的判断 | 设计决策（通过／打回）、用户反馈、待迭代问题、上线标准 |
| 干系人同步 | 跨部门或对外，报状态、要批准、要升级 | 状态概览、已获批准、升级事项、下次同步 |

亚型增量节同样适用「上限非配额」：某个追加节没内容就删。一对一不涉及职业发展就删掉该节，不留空标题。

## 通用骨架（访谈／播客／讲座／其他）

| 会议版章节 | 通用版名称 | 说明 |
| --- | --- | --- |
| 会议基本信息 | 内容基本信息 | 内容主题／来源／时间／主讲人或参与人；材料没给的省略该行 |
| 会议结论 | 核心结论 | 首段两到三句，写「本次内容」或「本次分享」的要点结论 |
| 关键决策 | 关键要点 | 无决策时写核心观点；**不把单人观点写成已达成共识** |
| 待办事项 | 行动事项 | 无行动时整节删掉，不硬凑 |
| 待定与开放问题 | 待定与开放问题 | 主讲人未展开、材料未覆盖的问题 |
| 上期行动项回顾 | 上期事项回顾 | 仅有上期材料时设 |
| 会议内容 | 内容详情 | 按主题分节，不按时间顺序复述 |

### 访谈专属节

在「核心结论」之后、「关键要点」之前插入两节，因为访谈的第一价值是原话，不是归纳：

- **受访者原话**：逐条引述，每条标明说话人；原话必须来自转写稿，不得改写后仍加引号。只删语气词与口头重复，不改语义。
- **解读与推断**：分析者的判断单独成节，注明依据哪几句原话。**这一节与「原话」合并不写。**

### 播客专属节

- **章节时间戳**：按话题列「时间 · 话题」，从 0:00 起。这是唯一保留时间戳的非会议类型。
- **金句**：逐条引述并附时间戳。
- **提及资源**：书中提到的书、工具、人名、链接。没有就删掉本节。

### 讲座专属节

- **术语定义**：讲授中引入的术语及其定义。
- **案例与例证**：讲者用来支撑观点的具体案例。
- **引用与参考**：讲者点名的书、论文、人名。没有就删掉本节。
- **工具与资源清单**（吸纳自 Fabric `summarize_lecture`）：讲者提到的具体工具、软件、文献，一行一条附一句说明。
- **一句话要点**（同上）：用一句话概括这场讲座最重要的结论，不超过 30 字。放在核心结论段末，不单独占节。

### 辩论／强分歧材料专属节

- **分歧与转折条件**：主要分歧是什么；各方论点；**什么证据能让他们改变立场**（吸纳自 Fabric `summarize_debate`）。

这条对「研讨交流」性质的会议同样适用，不必是正式辩论。判断依据：会上出现了明确的立场对立，且有人给出条件性表述（「如果能确认××，我就同意」）。

## 时间戳规则（按场景区分）

| 场景 | 是否保留时间戳 | 理由 |
| --- | --- | --- |
| 会议纪要（常规/正式/复盘/站会） | 不保留 | 纪要是决策记录，读者要的是结论不是定位 |
| 访谈 | 不保留，但原话节可标注区间（如 12:30-13:05） | 便于回原文核对 |
| 播客 | 保留（章节 + 金句时间戳） | 导航与传播的核心 |
| 讲座 | 保留（术语与案例首次出现的时刻） | 回看定位 |

时间戳一律按原文实际时刻写，不估算、不补齐。

## 输出变体

默认交付**完整版**。按用户要求或受众需要派生三个变体（数字与措辞必须与完整版一致，只做删减、不做改写）：

- **一页版**（给未参会的管理层）：会议基本信息 + 会议结论 + 关键决策 + 待办事项 + 待定与开放问题；删除会议内容与上期回顾。
- **任务清单版**（贴群／进看板）：仅待办事项，按「@责任人 完成时间 待办事项」逐行输出，不加编号与说明。
- **会前简报版**（吸纳自 pm-claude-skills 的 `briefing-note`）：用于「给决策者的单页简报」，五段结构——事由（两行说清是什么、为什么现在到他手上）、背景（最少必要上下文，列日期与既有进展）、关键考量（影响决策的事实、风险、各方立场，用条目不用散文）、建议或所需决策（建议做法加一句理由，或需要谁拍板）、联系人。**控制在一页**，细节放附件、只引用不展开。

### 完整分层版结构

把七节按议题展开成两级，不是另一套口径。结论、决策、待办的字句与默认版完全一致，只多支撑材料。
**骨架里的「一、二、三」是说明层级用的行文标记，落稿时章节标题不写编号**（`formatting.md` 明令，编号由 Word 自动生成）。校验器会剥掉标题前的编号再比对，但没必要给自己制造麻烦。

```
会议基本信息（主题 / 时间 / 地点 / 主持人 / 参会方 / 记录人 / 会议性质）

会议决策摘要
  背景概况       —— 一段话讲清这件事的由来与规模
  本次核心结论   —— 逐条列已定事项
  当前状态       —— 已批复 / 待复议 / 待补充材料

项目或议题背景
  现状问题       —— 表格：维度 / 现状
  涉及范围       —— 表格：分项 / 规模 / 说明

关键议题与讨论
  每议题一小节，固定三段：各方意见 → 分歧点 → 会议结论（未决写「未决」）

风险评估
  表格：维度 / 判断 / 依据（判断只取「可行 / 待补 / 待核 / 不可行」四档）

待决问题与风险
  逐条：未决什么 → 影响什么 → 卡在谁那里

行动项
  表格：事项 / 责任人 / 完成节点

会议结论与后续安排
  已认可 / 未决事项 / 下一步（含时间点）
```

三条使用约束：**二是可选节**，材料没给项目背景就删整节；**四与五不重复**，风险评估写判断与依据，待决问题写卡点与推进；**七是收尾不重复**，「已认可」从一二摘，「未决」从五摘。

判断是否用分层版的标准只有一条：读完默认版会不会有人追问「这个判断的依据是什么」。会追问就用完整版，不会就用默认版。

## 会前叙事文档模式

用于方向性、资源投入或重大变更类会议的**会前准备**（叙事文本，不用 bullet 堆砌；总长六页以内）：

1. 背景与现状（含关键数据）
2. 目标与要解决的问题
3. 备选方案对比（每案利弊、成本、风险）——**每个方案都要 steelman**：把该方案最强的版本写出来，而不是可打的稻草人（吸纳自 pm-claude-skills 的 `decision-meeting-format`）
4. 倾向建议及理由
5. 风险、依赖与预案
6. 需要会上决定的事项——**明确写清谁拍板**（人名或规则），不写「大家对齐」

此类会议的事后纪要以「会议结论 + 关键决策 + 待办事项」为主，讨论细节从简。
