# 待办提取口径

主文件 `SKILL.md` 只说「去提取待办」，本文件给出具体判据。核心区分三件事：什么是真行动、什么是孤儿、什么根本不该提。

## 一、先分清四类产出物

| 类型 | 判据 | 落到哪节 |
| --- | --- | --- |
| 行动项 | 有承接人 + 明确动作 + 强度为确定 | 待办事项表 |
| 软承诺 | 有承接人，但表述带「尽量／看看能不能／有空时」 | 待办事项表，优先级「低」，备注写「强度：软性」 |
| 无人认领 | 提出了该做，但**没有任何人承接** | 无人认领事项节 |
| 开放问题 | 未决、疑问、需后续确认，无承接动作 | 待定与开放问题 |

## 二、Action 与 Wish 的判别（吸纳自 pm-claude-skills 的 meeting-action-extractor）

真行动有两个必备特征：**隐含的承接人** + **一个有人同意去做的动词**。

| 说法 | 判定 | 原因 |
| --- | --- | --- |
| 「我周五前把材料发你」 | 行动项 | 第一人称承接 + 明确动作 + 时限 |
| 「孙磊你周五前给一下」 | 行动项 | 承接人被指派（若对方应答则更确定） |
| 「这个事我再看一下」 | 软承诺 | 有承接人，动作模糊 |
| 「我们应该重视这个问题」 | 不提取 | 表态，无动作无承接人 |
| 「应该有人去问一下口径」 | **无人认领** | 有该做之事，但「有人」不是承接人 |
| 「回头得找个人盯一下」 | **无人认领** | 同上 |
| 「大家会后跟进」 | **无人认领** | 「大家」不是承接人，备注注明会后另行分派 |

**关键判据**：如果这句话里找不出一个具体的人名或「我／你＋姓名」，它就是孤儿，不是行动项。

## 三、孤儿任务的处理（Orphan）

孤儿不等于丢掉。丢了等于「会上有人提过但没人管」这件事从记录里消失，下次再没人想起。

处理方式：单列「无人认领事项」节，每条写三样——**原话要点、提出者与时刻、待定的是「指派给谁」还是「是否要做」**。

```
### 无人认领事项

- 「应该有人去问下老张那边的口径」——提出者：说话人0（28:10）；待定：指派给谁，或确认不必做
```

读者拿到纪要后能据此决定「指派」或「放弃」，这比悄悄丢掉或塞进待办表都强。塞进待办表会让「待定责任人」的行数虚高，掩盖真正有人负责的任务。

## 四、识别线索

「X 会跟进／X 负责…」→ 承接人；「周五前／月底前／下周内」→ 完成时间；「尽快／紧急」→ 优先级高；「有空时／最好能／以后再说」→ 优先级低；第一人称承诺 → 说话人即责任人；句末疑问、「需要确认…」→ 开放问题，不进待办表（已明确承接人加承接动作的除外）。

**请求方向核对**：A 请 B 办事而 B 推回给 A 的，责任人是 A。

## 五、负向过滤

- 「我们应该重视／这个问题需要关注」这类表态句不构成待办。
- 方向尚在讨论、无承接人的意向表述不进待办表（进无人认领节）。
- 建议与对冲承诺（「可以考虑」「尽量」「条件允许的话」）不写成确定任务：有承接人的按软承诺入表，无承接人的不提取。
- 举证工作量的举例不是任务分配。
- 玩笑式表述、已被明确否掉的提议不进表。

## 六、字段填法

**责任人**：材料没给写「待定」，不推断，不臆造姓名。责任人可以是部门（此时说话人归属比对跳过）。

**完成时间**：必须换算成具体日期。会上说「周五前」「下周三」「月底前」，纪要发出几天后就看不出是哪天。换算基准只有一条：以会议时间所在周为基准周——「本周X」＝该周第 X 天，「下周X」＝次周第 X 天，「周X」未限定时取会议日期之后最近的那个 X；「月底前」＝当月最后一日，「下月初」＝次月第一日。**会议时间缺失或无法解析时不做换算**，保留原话照录。原文矛盾或跨月歧义时照录原话并归入待定与开放问题说明歧义。

**优先级**：阻塞他人工作或被明确标注紧急的为高；未标注的默认为中并在备注写「优先级未明示」；锦上添花、无时限的为低。只取原始记录的语言线索，不自行加权。

**状态**：未开始／进行中／受阻／完成／取消／待定。本次会上无法判断进度的填「待定」。

**出处**：备注写「出处：00:35 说话人1」。**优先锚承接人自己确认的那一段**（「好，我周五前给」），不锚派活那一段（「孙磊你周五前给」）——锚到派活段会让责任人与该段说话人天然不一致，产生误报。只有会上没有确认句、责任人被单方面指派时，才锚派活段。

**强度**：软承诺写「强度：软性」，确定承诺不写或写「强度：确定」。

**事项表述**：以待办动词开头、具体可执行、带足够上下文，让不看原始记录的人也知道要做什么。写「修复移动端结算页按钮无响应问题」，不写「处理按钮那个事」。

## 七、编排与滑期

多条待办先按优先级（高→中→低）排序，同级内按完成时间由早到晚。

**滑期约定**：同一项行动项滑期两次后，必须在会上当场改责任人、改完成时间或改范围，不允许悄悄顺延。顺延而三样都不动，说明这件事实际没人负责，纪要里按「待定」处理并归入待定与开放问题。这条校验器判不了，靠出稿时对着上期表格自查。

## 八、质量自检

- 每条待办有责任人吗？缺的填了「待定」而不是编造？
- 每条有完成时间吗？相对时间换算了吗？
- 表述是动词开头且具体吗？
- 有没有「应该有人…」这类被误当行动项写进待办表？应在无人认领节。
- 有没有真正有人认领的任务被漏掉？
- 每条备注有「出处：」吗？锚的是承接人确认段吗？
- 软承诺标了「强度：软性」吗？确定承诺有没有被误标？
