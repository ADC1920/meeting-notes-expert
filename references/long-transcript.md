# 长转写稿分块与归并

材料超过一屏上下文时（经验线：转写稿正文约 8000 字以上，或原音超过 1 小时），一次通读会丢细节：人名前后不一致、后半场的决议覆盖前半场的表述、数字被静默改写。分块不是为了让模型「读完」，是为了让每一块都有明确的归属边界，归并时能核对得上。

## 一、什么时候必须分块

| 信号 | 处理 |
| --- | --- |
| 正文超过约 8000 字 / 原音超过 1 小时 | 分块，按下面的切法 |
| 正文不足 8000 字但一次性读完后仍能完整复述议题脉络 | 不分块，直接通读 |
| 材料本身按议程分节（有小标题或「接下来第三个议题」这类转场） | 优先按议程切，议程边界比字数更可靠 |

分块与否的唯一判据是**能不能保持全局一致性**，不是字数本身。宁可分块后多一道复核，也不要读完就忘前半场。

## 二、切在哪里：只切说话人轮次边界

**核心约束：不要切在一个人说话的中间。** 切在句子中间会让后半句失去说话人归属，归并时无法判断这句话是谁说的，最容易产出「某人提出」这类无主表述。

- 正常情况：在「上一个人说完、下一个人开口」的位置切。
- 单轮超过一块预算（一个人连说很久，如汇报或陈述）：**先按句号/问号断句**，再拼成块；每一片都重新挂上「说话人：」前缀，保证丢进任何一块时都知道是谁在说。
- 前后各留约 5% 的重叠：让相邻块共享一小段上下文，避免跨块的议题被切成两半后两边都读不懂。重叠段在归并时按内容去重，不重复计入。

`scripts/chunk_transcript.py` 按以上规则切块，可直接用：

```bash
python "$MNX_SCRIPTS/chunk_transcript.py" 会议原文.txt --budget 8000 --out-dir .tmp/chunks
```

输出 `chunk-01.md`、`chunk-02.md`…，每块头部标注该块的起止时间戳与覆盖的说话人。低于预算的稿子不会被切（只产出一块），不必先判断要不要分。

## 三、怎么归并

1. 逐块提炼局部要点，但**只记「说了什么、谁说的、什么时间」**，不做跨块判断（这一块看不到别的块，任何全局结论都会错）。
2. 全部块读完后统一归并：议题按内容归并（同一议题散在多个块时合并），人名与专名按高频写法归一，数字与日期逐条核对。
3. **归并稿禁止出现指代前文的表述**：「前半段提到」「以上材料显示」「前 N 个块」「根据前面的摘要」——读者看到的必须是一份完整纪要，出现这类词说明归并没做完，是把拼接稿交出去了。
4. 归并后必做的三项复核：**人名一致性**（同一个人是否出现两种写法）、**数字一致性**（同一事实的数字前后是否矛盾）、**时间线一致性**（决议顺序与时间戳是否倒置）。

## 四、分块带来的已知风险

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 跨块议题被切断 | 同一议题在两个块各记一半，归并后重复或矛盾 | 5% 重叠 + 归并时按议题合并 |
| 后段决议覆盖前段 | 前半场说「按 A 办」，后半场改「还是 B」 | 归并时以后段为准，若确实反悔要在「会议内容」写明转折 |
| 全局数字统计失真 | 每块各报一部分，归并时相加得出原文没有的总数 | 独立出现的估算值不相加（见主文件「数字与口径保真」） |
| 说话人归属漂移 | 切块后某人的发言被算到别人头上 | 只切轮次边界 + 每片重挂前缀 |

## 五、不需要分块的情形

站会、1:1、短会（半小时内）通常远低于阈值，直接通读即可。分块本身有成本（多次提炼、一次归并），不要为「显得严谨」给短文分块——那只会引入归并错误。
